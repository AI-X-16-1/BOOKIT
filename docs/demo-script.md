# docs/demo-script.md — 시연 대본 (심사용)

제출 2026-09-20, 심사 기간 ~2026-10-05. 배포: https://bookit-edu.vercel.app

**한 권으로 전부 보여준다 — 「운수 좋은 날」(현진건, 3장).**
읽기 → 표지 퍼즐 → 체크포인트 → 캐릭터 부화 → 독후감 → 보스전(AI 검증) → 도감이
이 책 하나로 끊기지 않고 이어진다. 시드가 이 책을 **1장만 읽은 상태 + 초고 저장됨**
으로 두고 있어서, 시연이 중간부터 자연스럽게 시작된다.

---

## 0. 시연 전 (1분)

```bash
npm run audit:prod        # 배포·시연 로그인·RLS·법적 고지 44항목. 전부 ok 여야 한다
npm run demo:reset        # 미리보기(읽기만). 시드가 틀어졌는지 대조한다
```

> ⚠️ **데모 계정으로 "통과"를 연습하지 말 것 (#159 가 고쳐질 때까지).**
> 대본 4~5단계는 시드가 만들어 둔 **초고**(9/3)를 통과시키는데, `demo:reset` 은
> **기준일(9/16) 이후에 만들어진 행만** 지운다. 그 초고는 기준일 이전이라
> 되돌려지지 않는다 — 책갈피 +50 이 남고, 독후감이 `passed` 로 굳어
> **1단계의 "초고 저장됨 · 이어서 쓰기" 카드가 사라진다.**
> 게다가 캐릭터 복구가 `운수 좋은 날` 을 두 번(통과작 stage 2 · 시드 stage 0) 넣어
> upsert 가 통째로 실패하고 **도감이 비워진다.** 2026-09-18 실제로 났고 손으로 복구했다.
>
> 연습이 필요하면 **다른 책**으로 하거나, 통과 직전까지만 간다.
> 이미 냈다면 `seed.sql` 값으로 손복구해야 하고, 순서는
> **원장 → 검증 → 빈틈** 이다 (`verifications.gap_id` FK, 반대로 하면 `23503`).

`demo:reset` 이 되돌리는 것: 기준일 이후 독후감·검증·책갈피·읽기 기록·체크포인트,
장르 도장, 연속 기록(7일, `last_passed_on` = 오늘 — **심사자가 오늘 통과하면 이어진다**),
캐릭터(최종 9 · 부화 1 · 알 1 = 11마리), 읽기 진행(금도끼 전 장 · 운수 좋은 날 1장).
잔액 1,240 을 확인하고 끝난다. 시드 독후감 12편과 books 는 안 건드린다.

**로그인**: `/auth/demo?as=student` · `/auth/demo?as=teacher` (구글 없이 들어간다).
로그인 화면의 시연 카드로도 같은 곳에 간다. `DEMO_LOGIN_ENABLED` 로 켜져 있고
2026-10-17 이후 자동으로 404 가 된다.

## 1. 홈 — "오늘은 어떤 책을 잡아볼까?" (30초)

화면에 있는 것: 책갈피 **1,240**, 반 순위 칩, 두 갈래 카드.

- **책 읽기** — `서재에서 이어 읽기 · 운수 좋은 날`, **33% 읽음 · 표지 조각 1/3**
- **독후감 쓰기** — `초고 저장됨 · 이어서 쓰기`

> 할 말: "홈에 갈래가 둘뿐이다. 읽거나, 쓰거나. 검색·추천은 각각 서재와 작성 화면
> 안으로 들어갔다 — 아이가 홈에서 길을 잃지 않게."

## 2. 서재 — 읽을수록 표지가 드러난다 (1분)

**책 읽기** 카드를 눌러 2장으로. 장 끝(마지막 쪽)에 닿으면:

- 표지 퍼즐 **1/3 → 2/3** — 768px 이상은 오른쪽 패널에 늘 보이고, **폰은 읽기 화면
  상단의 `2 / 3장 🧩` 칩을 눌러** 바텀시트로 연다 (사전과 같은 패턴, §8).
  칩은 한 장이라도 읽은 책에만 누를 수 있다 — 진행 기록이 조각의 재료다
- **체크포인트**가 뜬다 — 그 장 본문으로 AI 가 만든 한 문항

> 할 말: "조각은 읽은 장만큼 열린다. 체크포인트는 **책갈피를 주지 않는다** —
> 읽는 중에 이해를 확인만 하고, 통과하면 알이 깨진다."

한 문장이라도 답해서 통과 화면을 보여준다. 시간 제한이 없다는 점을 짚는다
(제한 시간은 보스전에만 있는 장치다).

## 3. 3장까지 읽기 — 알이 부화한다 (30초)

3장 끝에 닿으면 퍼즐 **3/3**, 캐릭터가 **알 → 아기 인력거**로 부화한다.

> 할 말: "마지막 장을 읽으면 부화한다. 진화는 DB 트리거가 올려서 화면 응답을
> 느리게 하지 않는다."

## 4. 독후감 — 초고 이어 쓰기 (1분)

하단 탭 **독후감** → 저장돼 있던 초고가 열린다. 두세 문장 더 쓰고 제출.

- **빈틈 분석** — 근거 없이 단정한 문장 / 뭉뚱그린 문장 / 감상만 남은 문장
- 빈틈 화면을 보는 동안 **질문은 뒤에서 미리 만들어진다**

## 5. 보스전 — AI 검증 (1분 30초)

질문이 화면에 뜬 뒤에 카운트다운이 시작된다(30~60초, `ANSWER_WINDOW_SEC`).

> 할 말: "질문은 제출할 때마다 새로 만든다. 재시도하면 **다른 빈틈에서 새 질문**이
> 나온다 — 외워서 넘길 수 없다. 채점은 맞다/틀리다가 아니라 세 축이다:
> 정합성 · 구체성 · 문체 일관성."

결과 화면(보라색 보스전 연출):

- 통과 → **잡았다!** · 보스 HP 0 · 책갈피 **+50** · 연속 기록
- 실패 → **놓쳤어요** · 무엇을 더하면 되는지 + **다시 도전하기** (벌처럼 보이지 않게)

> 실패를 일부러 한 번 보여주면 좋다 — "틀렸다" 가 아니라 "한 줄만 더" 로 말한다는 걸
> 보여주는 화면이다. 재시도에서 질문이 바뀌는 것도 같이 확인된다.

## 6. 도감 — 잡은 책이 캐릭터로 (30초)

통과 화면의 **도감에서 보기** 또는 하단 탭 **도감**.

- 「운수 좋은 날」이 방금 **눈물 인력거**(최종)로 들어와 있다
- ★ 등급 = 보스전을 몇 번에 잡았는지. 한 번에 잡으면 ★★★
- 못 잡은 칸은 **책 제목만** 보인다 — 다음에 뭘 읽을지 고르는 자리다

## 7. 교사 화면 (30초, 데스크톱)

`/auth/demo?as=teacher` — 반 랭킹, 학생별 통과 수·평균 점수·연속 기록.

> 할 말: "교사에게는 **독후감 본문이 절대 안 간다.** 점수와 통과 여부만이다.
> 보호자 링크도 같다. 정책은 DB 의 RLS 로 막혀 있어서 화면이 실수할 여지가 없다."

## 함정 (미리 알고 갈 것)

| 함정 | 어떻게 |
|---|---|
| 「금도끼」는 **1장짜리** | 펼치는 순간 퍼즐 100% + 부화가 한꺼번에 뜬다. 시연에 쓰지 말 것 — 조각이 하나씩 열리는 게 안 보인다 |
| 이미 답한 장을 다시 읽으면 | 같은 문항이 한 번 더 뜬다. 닫으면 그만이고 해롭지 않다 |
| LLM 왕복 | 빈틈 분석·채점에 몇 초 걸린다. 그 사이 화면이 비지 않게 만들어 뒀지만, 말로 덮을 구간을 미리 정해 둘 것 |
| 답변 창 | 질문이 **뜬 뒤** 시작한다. 빈틈 화면을 오래 봐도 시간이 깎이지 않는다 |
| 시연 뒤 | `npm run demo:reset` **미리보기로 대조**한다. `--write` 는 #159 가 고쳐진 뒤에 (위 경고) |
| 시드 대조표 | 잔액 **1,240** · 독후감 **12편** · 도감 **11마리**(최종 9 · 부화 1 · 알 1) · 읽기 진행 금도끼 전 장 + 운수 좋은 날 1장. 하나라도 다르면 시드가 틀어진 것이다 |
