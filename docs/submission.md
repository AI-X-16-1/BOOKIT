## 3. 해결하고자 한 문제

### "안 읽는 게 아니라, 이해가 안 되는 것"

학생들은 책을 읽고 있습니다. 문화체육관광부 「2023 국민독서실태조사」 기준 학생 종합독서율 95.8%, 연간 독서량 36.0권으로 2021년보다 오히려 늘었습니다. 그런데 이해도는 떨어졌습니다.

| 지표 | 수치 | 출처 |
|---|---|---|
| 중3 국어 학업성취도 "보통학력 이상" | 2019년 82.9% → 2024년 66.7% (−16%p) | 교육부 국가수준 학업성취도평가 (2025.7) |
| "학생 문해력이 과거보다 나빠졌다"는 교사 | 91.8~92% | 한국교총 등 교사 설문 |

독서량과 독해력은 별개 지표입니다. 읽는 양은 유지되는데 이해도가 떨어진다면, 필요한 것은 "더 읽게 만드는" 서비스가 아니라 **"제대로 읽었는지 확인하는" 서비스**입니다.

### 기존 방식의 한계

- **완독 체크·사진 인증** — 읽었다는 신고일 뿐 이해 여부를 확인하지 못함
- **독후감 제출** — 대필·복사·AI 생성을 걸러낼 수 없음. 교사가 한 반 독후감을 일일이 읽고 되물을 시간도 없음
- **퀴즈형 확인** — "주인공 이름은?" 같은 지엽 질문은 실제로 읽었어도 잊기 쉬워 억울한 오탈락이 생기고, 유명한 책은 안 읽어도 맞힘

### 우리가 정한 개입 지점

독해 습관이 굳기 전인 **초1~중3**을 대상으로, 학생이 **직접 쓴 독후감 문장**을 근거로 되묻습니다. 책 내용 일반이 아니라 본인 문장에 대해 "왜 그렇게 생각했는지"를 묻기 때문에, 줄거리를 외웠거나 남이 써 준 글로는 통과하기 어렵습니다. 반대로 정말 읽은 아이는 서툰 문장이라도 자기 근거를 말할 수 있습니다.

## 4. AI 활용 방식 및 결과

### 4-1. 3단계 검증 파이프라인

AI는 독후감을 "채점"하지 않습니다. **읽고, 되묻고, 답변을 봅니다.** 모든 호출은 서버에서만 일어나며 프롬프트 출력은 전부 JSON 스키마로 강제합니다.

```
독후감 제출
   │
   ▼
① 빈틈 분석 ─── 독후감을 책 내용과 대조해 논리적 빈틈 최대 3개 추출
   │             · 근거 없이 단정 — 판단은 있는데 어느 장면이 근거인지 없음
   │             · 뭉뚱그린 문장 — "여러 사건이 있었다"처럼 무엇인지 특정 안 됨
   │             · 감상만 남음 — "감동적이었다"처럼 인물·장면과 연결이 없음
   ▼
② 꼬리질문 생성 ─ 빈틈 하나를 골라 학생의 문장을 인용하며 "왜 그렇게 생각했어?"
   │             · 해석·근거형만. 지엽 사실 질문(이름·숫자)과 가정형("만약 ~라면") 금지
   │             · 매 제출마다 새로 생성, 재시도 시 다른 빈틈에서 새 질문
   ▼
③ 답변 채점 ──── 세 축으로 통과/미통과 판정 + 아이 말투의 짧은 피드백
                 · 논리 정합성 — 답변이 독후감의 주장과 이어지는가
                 · 구체성 — 장면·인물·대사 같은 근거를 댔는가
                 · 문체 일관성 — 독후감과 답변의 글쓴이가 같은 사람인가 (대필 탐지)
```

(④ **글쓰기 도우미** — 쓰기 전에 가이드 질문 하나를 보여주는 프롬프트는 완성되어 있으나 화면 연결이 아직이라, 제출 시점에 붙지 않으면 이 문단은 뺀다.)

### 4-2. 부정행위 방지 설계

| 장치 | 목적 |
|---|---|
| 질문 실시간 생성 (매 제출마다 다름) | 문제 은행 유출·공유 불가 |
| 답변 제한 시간 45초 (질문이 화면에 뜬 뒤 시작) | 다른 AI 창을 열어 답을 만들 시간 차단 |
| 학생 본인 문장 인용 | 책을 안 읽고 줄거리만 아는 경우 대응 불가 |
| 문체 일관성 축 | 독후감은 어른 글, 답변은 아이 글이면 대필로 판정 |
| 재시도 시 새 빈틈·새 질문 | 같은 질문 반복 학습 차단 |

### 4-3. 검증 결과 (모델 확정 전 캘리브레이션)

초등학생 수준으로 작성한 독후감 20건을 네 그룹으로 나눠 파이프라인 전체를 돌렸습니다.

| 그룹 (각 5건) | 기대 결과 |
|---|---|
| 잘 쓴 독후감 | 통과 |
| 읽었지만 뭉뚱그린 독후감 | 질문 받고, 성의 있는 답변이면 통과 |
| 안 읽고 쓴 독후감 | 미통과 |
| 대필·AI 생성 독후감 | 문체 불일치로 미통과 |

| 항목 | `gemini-3.5-flash` (대회 모델) |
|---|---|
| 대필 판별 (문체 급변) | **5/5** |
| 채점이 기대와 일치 | **17/18** |
| "읽었지만 뭉뚱그림" 그룹의 무리한 탈락 | 1/6 |

가장 경계한 것은 **정말 읽은 아이가 억울하게 떨어지는 것**입니다 — 이 서비스가 아이에게 벌을 주는 도구가 되면 안 되기 때문입니다. 기준을 "6건 중 2건 이하"로 잡았고 그 안에 들었습니다. 통과 기준은 환경변수로 두어 심사 기간 중에도 조정할 수 있습니다. (수치는 제출 직전 머지된 코드로 한 번 더 돌려 갱신합니다 — 상세는 `docs/submission-ai.md`.)

### 4-4. 실패를 벌로 만들지 않는 결과 화면

미통과 시 "틀렸다"가 아니라 **무엇을 더 쓰면 되는지**를 아이 말투로 알려주고 바로 다시 쓸 수 있게 합니다. 점수는 정답/오답이 아니라 세 축의 강·약으로 보여줍니다.

### 4-5. AI 밖의 설계 원칙

- **독후감 원문은 학생만 봅니다.** 교사·보호자는 점수, 통과 여부, 완독 수까지만. DB 행 단위 보안(RLS)으로 강제합니다.
- **개인 순위를 노출하지 않습니다.** 반 대 반 랭킹만 있습니다.
- **보상은 자체 포인트(책갈피)** — 통과 1건 50. 외부 쿠폰·열람권 API에 의존하지 않고, 책갈피는 책나무 성장·장르 도장판·반 대항전 순위로 이어집니다. 외부 기관 보상(도서관 연계 등)은 제휴가 확정된 뒤 붙일 로드맵입니다.

## 5. 사용 AI 툴 및 기술 스택

### 서비스에 탑재한 AI

| 항목 | 내용 |
|---|---|
| 모델 | **Google Gemini `gemini-3.5-flash`** (유료 티어) |
| 대체 모델 | `gemini-3.5-flash-lite` → `gemini-3.6-flash` (과부하·한도 시 자동 전환) |
| 호출 | 검증 3종(빈틈 분석 · 질문 생성 · 채점) + 글쓰기 도우미 + 장 끝 체크포인트, 배치로 장르 태그. 전부 서버 측 Route Handler에서만. 클라이언트에 API 키 노출 없음 |
| 출력 | JSON 스키마 강제 + 방어적 파싱 + 형식 불량 시 1회 재요청 |
| 부가 API | 국립국어원 한국어기초사전 (서재 단어 사전), 국립중앙도서관 서지정보 (도서 검색) |

### 개발에 사용한 AI 툴

**Claude Code (Anthropic)** — 5인 전원이 개발 전 과정에 사용. 스키마·RLS 설계, 프롬프트 튜닝과 20건 캘리브레이션 스크립트, 모듈 구현, PR 리뷰, 배포·운영 디버깅까지 Claude Code 세션 안에서 진행했습니다. 모듈별 소유자를 정하고 `CLAUDE.md`에 규칙을 못박아 5개 세션이 병렬로 작업해도 충돌이 나지 않게 했습니다.

### 심사위원용 체험 안내

1. 구글 계정으로 로그인 → **학생이에요** 선택 → 학년 선택 → 참여 코드 **`HBCLSB`** 입력 (데모 반 "한빛초 5학년 2반")
2. 책을 고르고 독후감을 씁니다 (100자 이상). 잘 모르겠으면 AI가 먼저 보여주는 가이드 질문을 따라가면 됩니다
3. 제출하면 AI가 빈틈을 찾고 질문을 하나 합니다. **45초** 안에 답해 주세요
4. 결과 화면에서 세 축 평가와 피드백을 확인합니다. 미통과면 바로 다시 쓸 수 있습니다
5. **나** 탭에서 책갈피와 성장 현황, **챌린지** 탭에서 반 랭킹, **서재** 탭에서 원문 읽기와 단어 사전을 체험할 수 있습니다

교사 화면을 보려면 다른 구글 계정으로 로그인해 **선생님이에요**를 선택하면 반이 만들어지고 6자리 참여 코드가 발급됩니다. 데스크톱(1024px 이상)에서 열어 주세요.
