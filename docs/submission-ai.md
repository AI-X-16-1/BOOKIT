## 2. AI 활용 방식 — 한 줄 요약

> 학생이 쓴 독후감에서 **근거가 빠진 문장을 AI 가 찾아**, 그 문장을 인용해 **"왜 그렇게 생각했어?" 를 되묻고**, 제한 시간 안에 한 답을 **정답 여부가 아니라 독후감과의 정합성으로 채점**한다.

기존 독서 인증은 "읽었다·안 읽었다" 만 확인한다. 책잇은 AI 를 **이해했는지 확인하는 질문자**로 쓴다.

## 3. AI 파이프라인

한 번 제출할 때 서버에서 AI 를 세 번 부른다. 모두 로그인한 사용자의 요청으로만, 서버(Vercel Route Handler)에서만 호출하고 API 키는 브라우저에 나가지 않는다.

```
독후감 제출 ─▶ ① 빈틈 분석 ─▶ ② 꼬리질문 생성 ─▶ (학생 답변, 45초) ─▶ ③ 채점 ─▶ 통과: 책갈피 50
                                                                           └▶ 미통과: 새 질문으로 재시도
```

### ① 빈틈 분석

독후감을 책 내용과 대조해 논리의 빈틈을 **최대 3개** 찾는다. 유형은 세 가지다.

| 유형 | 뜻 | 예 |
|---|---|---|
| 근거 없이 단정 | 판단은 있는데 어느 장면이 근거인지 없다 | "흥부는 착한 사람이라서 복을 받은 것 같다." |
| 뭉뚱그린 문장 | 무엇인지 특정되지 않는다 | "여러 가지 사건이 많이 나와서 재미있었다." |
| 감상만 남음 | 인물·장면과 연결이 없다 | "나는 이 책을 읽고 정말 감동적이었다." |

AI 가 돌려준 인용문은 **독후감 원문과 글자 단위로 대조**하고, 원문에 없는 문장은 버린다. 화면이 그 문장을 하이라이트하기 때문에, AI 가 문장을 다듬어 오면 학생은 자기가 쓰지 않은 문장을 지적받게 된다.

맞춤법이나 문장력은 보지 않는다. 근거가 있는지만 본다.

### ② 꼬리질문 생성

빈틈 하나를 골라 **학생이 직접 쓴 문장에 대해** 되묻는 질문 하나를 만든다.

- **해석·근거형만** 낸다 — "어느 장면에서", "왜 그렇게 느꼈는지"
- **사실 확인형은 내지 않는다** ("주인공 이름이 뭐였어?") — 실제로 읽었어도 잊을 수 있어 억울한 탈락이 생긴다
- **가정형은 내지 않는다** ("만약 ~라면?") — 답의 폭이 넓어 채점 기준을 세울 수 없다

책 일반에 대한 질문이 아니라 **학생 본인의 문장**을 묻는 것이 핵심이다. 유명한 책은 줄거리를 몰라도 그럴듯하게 답할 수 있지만, 자기가 쓴 문장의 근거는 쓴 사람만 바로 댈 수 있다.

### ③ 채점

정답이 아니라 **세 가지 축**으로 본다.

| 축 | 보는 것 | 판정 |
|---|---|---|
| 논리 정합성 | 답변이 독후감의 주장과 어긋나지 않는가 | pass / weak / fail |
| 구체성 | 장면이나 인물을 특정했는가 | pass / weak / fail |
| 문체 일관성 | 독후감과 답변의 어휘 수준·사고의 복잡도가 비슷한가 | same / shifted |

- **통과 여부는 AI 가 아니라 서버가 정한다.** AI 는 세 축만 판정하고, 서버가 기준(`PASS_THRESHOLD`)에 맞춰 통과를 결정한다. 기준을 바꿔도 같은 답변이 다르게 채점되지 않는다
- 짧다고 감점하지 않고, 맞춤법·띄어쓰기는 보지 않는다
- 피드백은 아이에게 반말로 두 문장 이내. **미통과는 나무라지 않고 무엇을 더하면 되는지** 알려준다

## 4. 부정행위 방지 설계

AI 로 쓴 독후감, 다른 AI 창에 질문을 붙여넣는 답변을 막는 장치다.

| 장치 | 방식 |
|---|---|
| 학생 문장에 고정된 질문 | 책 일반이 아니라 본인이 쓴 문장의 근거를 묻는다 |
| 매번 새 질문 | 제출할 때마다 실시간 생성. 미리 유출될 질문이 없다 |
| 재시도해도 같은 질문 없음 | 이전 질문을 AI 에 넘겨 **다른 빈틈·다른 각도**로 새로 만든다. 같은 질문이 나오면 서버가 걸러 다시 만든다 |
| 제한 시간 | 기본 45초 (30~60초 조정). 다른 AI 창을 열어 옮겨 적을 시간을 막는다 |
| 시간은 서버가 잰다 | 화면의 카운트다운은 표시용이다. 질문을 낸 시각을 서버에 기록하고, 늦게 온 답은 서버가 시간 초과로 처리한다 (네트워크 오차 5초 허용) |
| 문체 급변 감지 — **양방향** | ① 독후감은 아이 글인데 답변만 어른 문체 (답변을 대신 씀) ② 독후감이 학년에 비해 지나치게 성숙한데 답변은 아이 문체 (독후감을 대신 씀). 둘 다 `shifted` 로 통과시키지 않는다 |

## 5. 신뢰성 — AI 출력을 믿지 않는 구조

| 장치 | 방식 |
|---|---|
| 형식 강제 | 모든 호출에 JSON Schema 를 넘겨 출력 모양을 강제한다 |
| 방어적 파싱 3겹 | ① 스키마 강제 → ② 어긋나면 본문에서 JSON 을 건져 다시 검증 → ③ 그래도 틀리면 무엇이 틀렸는지 알려주고 한 번 더 묻는다. 반쯤 맞는 값은 쓰지 않는다 |
| 일시적 실패 재시도 | 408·5xx·네트워크 오류는 짧게 물러섰다 다시 (총 대기 1.6초 이내) |
| 대체 모델 | 그래도 안 되면 대체 모델로 자동 전환. 심사 기간 내내 서비스가 살아 있어야 한다 |
| 튜닝 가능한 값은 환경변수 | 통과 기준·제한 시간·지급 책갈피를 코드 수정 없이 시연 직전까지 조정한다. 잘못된 값이 들어가면 기본값으로 돌아간다 |

### 채점 기준 검증 — 독후감 20건

초등학생 수준으로 쓴 독후감 20건을 네 무리로 나눠 실제로 돌렸다 (`npm run ai:calibrate`).

| 무리 (각 5건) | 기대 |
|---|---|
| 잘 쓴 것 | 통과 |
| 뭉뚱그렸지만 실제로 읽음 | 질문을 받고, 제대로 답하면 통과 |
| 안 읽음 | 미통과 |
| 대필·AI 생성 | 문체 급변으로 미통과 |

| 항목 | `gemini-3.5-flash-lite` (9/10) | `gemini-3.5-flash` (9/15) | `gemini-3.5-flash` + 구체성 규칙 (9/16) | **`claude-sonnet-5`** (9/16, 제출 모델) |
|---|---|---|---|---|
| 채점한 답변 수 | 18 | 22 — 빈틈 0개인 독후감도 핵심 문장으로 질문·채점 (#14) | 22 | **22** |
| 대필 판별 (문체 급변 `shifted`) | **5/5** | **5/5** | 5/5 | **5/5** |
| 채점이 기대와 일치 | 18/18 | 20/22 | 21/22 | **20/22** |
| "읽었지만 뭉뚱그림" 중 통과해야 할 답변의 실패 | 0/6 | 1/6 | 1/6 | **1/6** |
| 안 읽고 쓴 답변이 통과로 잘못 판정 | 0/5 | 1/5 | 0/5 | **0/5** |
| 잘 쓴 독후감 통과 | – (빈틈 0개라 채점하지 않음) | 5/5 (4건은 핵심 문장 질문) | 5/5 (4건은 핵심 문장 질문) | **4/5** (2건은 핵심 문장 질문) |

- 가장 경계한 것은 **실제로 읽은 아이가 억울하게 떨어지는 것**이다. 기준은 "6건 중 2건 이하 실패" 로 잡았고 세 번의 측정 모두 안에 들었다
- `flash` 에서는 잘 쓴 독후감 5건 중 4건이 빈틈 0개였다. 예전 흐름이라면 이 4건은 질문 없이 지나갔다 — 잘 쓴 대필이 검증을 피하는 구멍이라 핵심 문장 질문(#14)으로 막았고, 성실하게 쓴 5건은 모두 그대로 통과했다
- ✅ **안 읽음 오통과 1건을 막았다** (#78). 9/15 에는 **n3** (유명한 문장만 알고 쓴 「어린 왕자」 독후감) 의 답변 "가장 중요한 건 눈에 안 보인다는 게 감동적이어서요." 가 논리 pass · **구체성 pass** · 문체 same 으로 통과했다 — 따로 다시 돌려도 같은 결과였다
  - 원인: 채점 기준의 구체성은 "장면이나 인물을 특정했는가" 인데, **책의 유명한 문장을 되풀이하고 감상을 붙인 답**을 막는 규칙이 없었다
  - 고친 방법: 구체성 축에 "널리 알려진 문장·제목을 그대로 옮기고 감상만 붙인 답은 특정한 것이 아니다 — weak" 를 넣었다. 지금은 안 읽음 5건이 모두 기대대로 미통과다
  - **규칙 하나가 채점 전체를 흔든다는 것도 같이 배웠다.** 처음에는 "어느 장면에서, 누구의 어떤 행동에서 그렇게 봤는지가 답에 있어야 pass" 까지 넣었는데, 뭉뚱그림 무리(실제로 읽은 아이) 오탈락이 0/6 → **2/6** 으로 늘었고 두 번 돌려 같은 두 건이었다. 게다가 탈락 사유가 구체성이 아니라 **논리 축**이었다. 그래서 판단을 구체성 축에 가두고("다른 축으로 옮기지 마라") 짧은 답 보호를 다시 못 박아 1/6 으로 되돌렸다
  - 남은 한계: 채점 입력에는 책 제목만 들어가 **실제 장면과 대조하지는 못한다**. 원문 대조까지 하려면 채점에 본문을 넣어야 해서 이번 범위에서 뺐다
- **제출 모델은 `claude-sonnet-5` 다** (#54, 2026-09-16). 벤더를 바꿨으므로 같은 20건을 그 모델로 다시 쟀고, 위 표의 마지막 열이 그 결과다
  - 안 읽고 쓴 답변의 오통과 **0/5**, 대필 판별 **5/5** 로 가장 중요한 두 축은 유지됐다
  - 기대 일치가 21/22 → **20/22** 로 하나 줄었다. 줄어든 한 건은 **잘 쓴 독후감 w4** 가 논리 축에서 떨어진 것이다 (구체성은 pass). `claude-sonnet-5` 가 전반적으로 조금 더 엄격하다
  - 빈틈을 더 잘 찾는다. 잘 쓴 독후감 5건 중 빈틈 0개가 4건 → **2건** 으로 줄어, 핵심 문장 질문(#14) 경로를 덜 탄다. 그 경로가 필요 없어졌다는 뜻이 아니라 덜 자주 쓰인다는 뜻이다
- ⚠️ 모델이 또 바뀌면 그 모델로 다시 잰다

## 6-1. LLM 벤더 — Gemini 에서 Anthropic 으로 바꿨다 (#54, 2026-09-16 확정)

Gemini 로는 이 서비스를 운영할 수 없다. 약관에 초·중학생 대상 서비스가 금지돼 있고, **창구를 바꿔도 피할 수 없다**.

| 창구 | 조항 |
|---|---|
| Gemini Developer API | Additional Terms — "You must be 18 years of age or older to use the APIs" · API Client 가 "directed towards or is likely to be accessed by individuals under the age of 18" 이면 안 된다 |
| Google Cloud Vertex AI | Service Specific Terms **§20(d) Age Restrictions** — 같은 문장. §20(f) 는 위반이 **의심되면** 즉시 중단할 수 있다고 한다 |

심사 기간(~10/5) 내내 링크가 살아 있어야 하므로, 약관 위반을 안고 가는 것은 선택지가 아니었다.

세 벤더의 약관을 직접 확인했다. **전면 금지는 Google 뿐이고, 업계 표준이 아니다.**

| 벤더 | 미성년 대상 서비스 | 약관 근거 (2026-09-16 전문 확인) |
|---|---|---|
| **Google** | **금지** | Gemini API Additional Terms · Cloud Service Specific Terms §20(d) |
| OpenAI | 허용 — **보호자 동의 조건** | Services Agreement 금지행위 — "allow minors to use OpenAI Services **without** consent from their parent or guardian" |
| **Anthropic** | 허용 — **안전장치 조건** | Commercial Terms 에 나이 조항 없음 · AUP 가 "products serving minors" 를 별도 가이드라인이 있는 정상 유스케이스로 명시 |

Google 이 유독 엄격한 이유는 채널을 분리했기 때문으로 보인다 — 미성년자용 AI 는 학교 관리자 콘솔과 관리자 동의 체계를 갖춘 Workspace for Education 으로 따로 제공하고, 범용 개발자 API 는 막는다. 학교 계약 없이 K-12 를 대상으로 하는 서비스는 그 구조에 들어갈 자리가 없다.

즉 **벤더 선택은 성능 비교가 아니라 "이 서비스를 계약상 운영할 수 있는가" 의 문제였다.**

### Anthropic 이 요구하는 것과 책잇의 대응

금지 대신 가이드라인을 따르게 한다 — 연령 확인, 콘텐츠 필터링, 모니터링·신고 경로, **AI 와 대화 중임을 알리기**, 아동 개인정보 법규 준수.

| 요구 | 책잇의 대응 |
|---|---|
| 연령 확인 | 교사가 만든 반 코드로만 가입 · 온보딩에서 학년 입력 (자유 입력 불가) |
| AI 고지 | 검증 화면이 "AI 가 네 문장을 보고 묻는다" 를 전제로 설계돼 있다. 이용약관 초안에도 명시했다 |
| 콘텐츠 필터링 | 모든 호출이 JSON 스키마로 제약되고, 거부(`refusal`)는 코드가 따로 처리한다 |
| 모니터링 | 실패한 검증도 `verifications` 에 남는다 (+0점) |
| 아동 개인정보 | 만 14세 미만 법정대리인 동의는 **미구현** — 교사 반 코드 구조를 전제로 한 간소화 상태다. 교사가 반 코드를 받는 화면에 "보호자 동의를 받은 학생에게만 이 코드를 알려주세요" 를 표시하고(#95), 처리방침(`/privacy` §5)에 미구현을 명시했다 |

### 데이터 학습 미사용은 옵션이 아니라 조항이다

> "Anthropic may not train models on Customer Content from Services."
> — Anthropic Commercial Terms of Service, B. Customer Content (2026-09-16 확인)

Gemini 는 "무료 티어면 학습에 쓰이고 유료면 아니다" 라는 티어 조건이었다. Anthropic 은 켜고 끄는 설정이 아니라 계약상 기본값이다. 보관 기간은 Anthropic 공개 정책 기준 **수신 후 30일 이내 자동 삭제**다 ("We automatically delete inputs and outputs on our backend within 30 days of receipt or generation", privacy.claude.com, 2026-09-16 확인). 이용 정책 위반으로 자동 분류된 건만 최대 2년. 처리방침(`/privacy`)에 같은 내용을 적었다.

### 전환 결과 (9/16 실행)

| 확인 | 결과 |
|---|---|
| 인증·모델 조회 (`npm run llm:models`) | ✅ `claude-sonnet-5` 사용 가능 |
| AI 4종 스모크 (`npm run ai:smoke`) | ✅ 전부 통과. 호출당 **2.3~3.5초** — 이전 모델보다 빠르다 |
| 채점 기준 20건 재측정 (`npm run ai:calibrate`) | ✅ 완료 — §5 표의 마지막 열 |

코드 변경은 없었다. `providers.ts` 의 anthropic 경로가 `output_config.format` 으로 JSON 스키마를 강제하고 `refusal` 을 따로 처리한다. 바꾼 것은 환경변수 네 개뿐이다.

남은 확인 하나 — 대체 모델(`claude-opus-5`)로 넘어간 경우는 캘리브레이션 대상이 아니다. 과부하로 폴백하면 그 순간 채점 기준이 달라질 수 있다 — 다만 상위 모델이라 느슨해지는 방향은 아니다.
